# MediaLink 下载器 3.0 计划

## 范围

- 下载页同时接收 B 站和抖音的视频长链接、分享短链与分享文本，批量输入可混合两种平台。预览显示来源、标题、作者和时长。B 站继续提供分 P 和扫码登录。
- 抖音先验证游客网页播放。读取目标视频实际提供的完整画面与音轨，按返回的清晰度显示可选项，支持带声 MP4、仅 MP3 和两者同时输出。访问受限时给出原因。只处理普通视频。
- 两个平台共用队列、历史、去重、重试及导出。任务执行时重新解析媒体地址，明确选择的画质失效时给出提示。队列及历史显示来源。

## 技术设计

1. 用已实测的样片验证可随应用部署的解析方式。优先使用本机 Edge 的独立临时游客会话读取正常播放响应，仅接收匹配目标 ID 的视频数据。浏览器及媒体请求集中到抖音模块，设超时和取消。若实际运行需要额外依赖或平台提示登录，则在应用中说明。
2. 将共用模型、链接识别、队列和媒体封装移入中立命名的包，B 站和抖音的解析分别放在平台模块。来源与视频 ID 共同作为任务身份。原数据库增加来源字段，历史数据默认为 B 站，保留原任务 ID、分 P、状态和文件路径。
3. 下载内核支持分离音视频和单文件带声流，继续校验分辨率、时长和音轨。手选同档重试、临时文件清理、原轨道封装及并存文件命名沿用 2.0 的行为。
4. 统一应用、构建产物、源码包和仓库名称为 MediaLink Downloader。保留原仓库历史、标签与公开可见性。验收后更新仓库名称、简介、主题、README、变更记录和标签；便携包在本机交付。

## 验收

- 审查链接来源、浏览器进程清理、数据库升级、跨平台去重、播放地址刷新、音频提取、失败隔离和线程退出。
- 跑原有与新增自动化测试。实测抖音样片及 B 站样片在同一队列完成，核对 MP4、MP3 与所选画质，查看历史并重启验证持久化。
- 验证从旧版数据升级、便携 ZIP 解压启动、真实运行依赖和 GitHub 新旧仓库地址及版本标签。

## 审查和实测

- 浏览器使用独立临时目录和回环调试连接，只读取与目标 ID 匹配的抖音播放响应。核对了超时和取消时的进程清理。下载分离轨道及带声文件均经过封装和完整性校验。
- 24 项自动化测试通过，覆盖目标 ID 匹配、横竖屏档位、来源去重、旧库迁移及原队列行为。
- Windows 桌面实测混合导入两平台链接、隔离无效项、两平台 1080P 带声 MP4 和 MP3、抖音手选 720P 及仅 MP3、查看历史与重启恢复。两平台成品通过完整解码。
- 便携 ZIP 解压后启动，在 EXE 中继续等待的抖音任务。完成后验证历史状态及 MP3 的完整解码。
- 抖音样片使用未登录会话。其他投稿的画质取决于网页当时返回的轨道；需要登录或验证的抖音页面属于当前游客解析范围之外。
