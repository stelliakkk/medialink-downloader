| 问题 | 实施内容 | 回归证据 |
| --- | --- | --- |
| R1 素材完整性 | 图片、片段和配乐在发布前通过 FFmpeg 严格解码；失败刷新地址重试一次，仍失败则不发布成品目录。取消信号继续生效。 | 截断 MP4 的头部可读但被拒绝；损坏图片不发布；第二次返回正常文件时恢复成功。 |

| R5 封面容错 | B 站封面函数覆盖 urllib3 HTTPError，失败退回空封面。 | 注入 ProtocolError 后返回空封面；取消异常仍向上传递。 |
| R6 构建环境 | try/finally 恢复 TMP、TEMP、PATH、PYTHONPATH、Qt 与 PyInstaller 环境及工作目录；构建前运行测试。 | 模拟构建中途失败后环境和目录恢复；实际成功构建的恢复结果另见下文。 |
| R7 错误诊断 | 通用异常显示中立提示和 `ML-` 编号；轮换日志仅保存异常类型、操作及代码位置。 | 向异常正文注入模拟 cookie 和签名 URL，界面和实际日志均未出现这些值。 |

补充修复：当前 FFmpeg 将动画 WebP 报为 `webp_anim`。识别表已支持该容器和编码；选择 PNG 时仍保留原动画。使用真实生成的 GIF、动画 WebP 验证了原始字节不变。

去重的保守规则：如果当前某个分 P 的最高档位未查询，不使用旧的已完成记录阻止新下载；等待/运行中的同类“最高可用”请求仍会去重。其他分 P 不继承当前分 P 的快照；批量普通视频会在预解析时查询当前最高档位。

## 保留的能力边界

- 普通视频的 MP4 导出目前仍要求有音轨；无音轨视频支持属于后续功能扩展。
- 素材模式配乐保留源格式；单独选择 MP3 输出才会转换。
- 实况照片保存为静帧和独立短片，没有重建手机原生动态照片的配对元数据。
- 网络取消需等待当前同步请求结束或超时，但不会再开始下一条 B 站请求。
- 图文素材完整解码会增加处理时间，长视频片段尤其明显，过程中可以取消。

本轮功能修复先在本机验收；后续按用户要求将源码、独立 EXE、完整便携包及源码材料发布到 GitHub v3.0.6。发布文件清单见 [版本说明](../releases/v3.0.6.md)。
